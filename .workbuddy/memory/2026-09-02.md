## iPhoneOrder 扩展升级 v1.3（修复登录选择器 + 插件报错）

### 用户反馈
加载 v1.2 测试：购物袋结账 → 登录页后仍卡住，控制台报错：
- `Uncaught TypeError: runtime.sendMessage(...) No matching signature`
- `Error in event handler: tts.speak(...) No matching signature`
- `doSignIn: account input not found after waiting`

### 问题根因
1. 新版 Apple ID 登录框是 `type="text"` / 动态渲染的通用输入框，旧选择器只覆盖 `type="email"` 导致找不到；
2. `popup/page.tsx` 中 `chrome.runtime.sendMessage()` 空参数调用，Chrome MV3 不允许多重载下的空参数；
3. `service-worker.js` 中 `chrome.tts.speak(text, voiceOption, {'enqueue': true})` 把 options 对象传到了第三个 callback 参数位置；
4. 新版"继续"箭头按钮不一定在 form 内，原 `findSubmitBtn` 查找范围不足。

### 代码改动
- `app/scripts/content/doSignIn.ts`：
  - 账号输入框候选增加 `input[type="text"]`、`input#account_name_text_field`、autocomplete=username、placeholder/aria-label 智能回退；
  - 新增 `findAccountInput()`：先精确候选 → 登录容器内第一个可见非密码输入框 → 全局按 placeholder/aria-label 匹配；
  - 新增 `findContinueBtn()`：优先输入框父容器内可见按钮，再全局候选，最后回车 `dispatchEvent(Enter)`；
  - 保留两步式逻辑：填账号 → 点继续 → 等密码框 → 填密码 → 点登录。
- `app/(pages)/popup/page.tsx`：空 `chrome.runtime.sendMessage()` 改为带 `{data:'bellring', extensionId, voiceInfo}` 的合法调用。
- `app/scripts/content/playSystemNotifacation.ts`：`sendMessage` 增加空回调参数，提升 MV3 兼容性。
- `extension/service-worker.js`：循环 `tts.speak(text, Object.assign({}, voiceOption, {enqueue: s>0}))`，把 enqueue 合并进 options。
- `extension/manifest.json`：version 1.2→1.3
- tsc --noemit 通过，完整构建成功

## iPhoneOrder 扩展升级 v1.4（登录表单在 iframe，all_frames 注入）

### 用户反馈（v1.3 仍卡登录页）
控制台无 doSignIn 前缀日志，仅：顶层反复 `sleep seconds: 0.8`（waitForElem 空轮询）；关键线索：`signin?frame_id=auth-tasfvg51-...` 的 iframe document，且报错 `from origin 'https://idmsa.apple.com.cn'` 请求字体被 CORS 拦。

### 根因（重要架构认知）
**登录表单渲染在嵌套的 signin iframe 内**（origin = idmsa.apple.com.cn，pathname=/signin，URL 带 frame_id 参数）。而 content-script 默认 `all_frames:false` 只注入顶层 frame → 顶层 content-script 的 `document.querySelector('#signin-container')` 永远看不到 iframe 内表单，doSignIn 在顶层空转 40s 后超时返回（无 doSignIn 前缀日志因还没到打印点）。secure 结账登录宿主页只是容器。

### 代码改动
- `extension/manifest.json`：content_scripts 加 `"all_frames": true`，使 signin iframe(idmsa.apple.com.cn，仍匹配 *.apple.com.cn) 也注入 content-script 去操作表单
- `app/scripts/content/index.ts`：contentRun 里 `addTipsToPage` 仅 `isTopFrame` 时执行（避免每个 iframe 重复塞浮动小窗）；加 URL 日志
- `app/scripts/content/doFroApplePages.ts`：登录分支判定优化——用 isTop 检测「顶层 /shop/signIn 宿主页无 form」则跳过（表单在其内嵌 iframe，避免顶层空等）；其余命中 /signin 的 frame（含 frame_id 的登录 iframe）交 doSignIn 等待表单出现
- `extension/manifest.json`：version 1.3→1.4
- tsc --noemit 通过，完整构建成功

### 交付
- `iPhoneOrder_extension_v1.4.zip`（78 文件，3MB）位于项目根

### 经验沉淀
- 苹果结账登录流程：secure.www.apple.com.cn/shop/signIn 是宿主容器，真实 Apple ID 表单在跨域 iframe `idmsa.apple.com.cn/signin?frame_id=...`（两步式：Apple ID→continue→密码）
- 抓包 secure/signIn 直接 curl 返回空(需完整 cookie+登录态)；分析 DevTools 折叠相对路径 + CORS origin 报错可推断 iframe host
- 扩展操作 iframe 内表单必须 content_scripts all_frames:true（宿主页看不到 iframe DOM，也无法跨域 querySelector，只能靠 iframe 自己的 content-script）
