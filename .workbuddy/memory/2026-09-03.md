## iPhoneOrder 扩展 v1.7（重庆区划调整 + 取货 404 排查）

- 背景事实（已检索核实）：2025-11 国务院批复撤销重庆江北区、渝北区，设立两江新区（2026-01-25 挂牌）；Apple 官网取货地址已改「重庆市两江新区」。老配置里的 江北区/渝北区 在苹果侧已失效，可能是取货点击后 checkoutx 请求异常继而 404 的根因之一。
- `app/shared/location/county.json`：重庆「市辖区」列表删除 江北区(500105)、渝北区(500112)，新增 两江新区(占位 id 500157)。
- `app/shared/constants.ts`：新增 `normalizeDistrictName(province, city, district)`，运行时把旧区名 江北区/渝北区 → 两江新区（重庆）。
- `checkoutSteps.ts` / `getStoreCanPickInfo.ts` / `storeSearchInPage`：请求与 UI 选择统一走 normalizeDistrictName。
- `app/(pages)/options/page.tsx`：老配置区名失效时回退选中「两江新区」而非列表第一个（万州区）。
- manifest 1.7，构建并交付 `iPhoneOrder_extension_v1.7.zip`。
- 待验证：若改区名后取货仍跳 `/shop/404`，需要用户提供跳转前一刻的控制台日志（关注 partNumber/x_aos_stk、GMfetch、goOrderSteps 计数行），再判断是会话风控还是 init_data 解析失败触发的 reload。

## iPhoneOrder 扩展 v1.8（取货 541/404 死循环防护）

- 用户日志实证：v1.7 后点「我要取货」→ **苹果页面自身** `POST checkoutx/fulfillment?_a=selectFulfillmentLocationAction&_m=checkout.fulfillment.fulfillmentOptions` 返回 **541**（非插件请求），约 2s 后整页跳 `/shop/404` → errorRecover 清 cookie 回购物车 → 自动再结账 → 再 404 死循环。请求体已带「两江新区」，排除区名问题。541 根因指向苹果服务端拒绝该 checkout 会话切换到店取货（会话被风控 / SKU 不可自取，苹果社区存在手动购买同样被导 404 的案例）。
- `errorRecover.ts`：新增 404 自愈刹车 —— storage.sync 记 `orderRecoverLog`{count,firstTs}；10 分钟内自愈 ≥3 次 → 写 `orderAutoPauseUntil` = now+10min，暂停自动下单；导出 `getAutoPauseRemainMs()`。
- `doFroApplePages.ts`：入口 autoRecover 后检查暂停（暂停中不点结账/登录/取货）；checkout fulfillment 分支点「我要取货」前随机等 1.2~3s（会话就绪），`isSegmentedSelected` 检测已选中则跳过点击（防重复触发 selectFulfillmentLocationAction），点击后再等 0.8~1.5s 才 getPageInitInfo。
- manifest 1.8，构建并交付 `iPhoneOrder_extension_v1.8.zip`。
- 待用户验证 + 建议做手动对照：无痕窗口关扩展，把 MG034CH/A 手动加购走到「我要取货」，若同样 404 → 苹果侧 SKU/区域不可购，需等 iPhone 18 新 SKU（9 月中发布后更新 constants 型号表）。
